Kanji, a New Kind of Model

Kanji reads a conversation, a document or a broadcast once, as it arrives, and keeps a table of what matters in it up to date: who and what is in it, and every value as it changes. It writes no text of its own.

A new kind of model

A System 1 State Model state from a stream

Psychologists call the fast, automatic way of thinking System 1: reading a face, a sentence or a scoreboard at a glance. Language models today work the slow way: they write out every answer a token at a time, and to keep track of something they write it all out again. Kanji is a System 1 model. It reads each line once and its table follows: new people, things and events are added, values change, and what has ended is retired. Each change comes with a probability and points back to the words it came from.

  • 0tokens generated: every value is read from the text or chosen among your schema's options, never written
  • 157 msto read a line and update the table, on the mean, on an M4 Max; 72 ms the median
  • 1M tokensread with memory flat: it carries the table, not the transcript

What it gives you

A table, kept current
The objects your schema names (people, tasks, orders, plays, attacks) with their fields, from a name or a number to a choice or a link between two objects. As the text goes on, Kanji adds them, changes their values and retires what has ended.
Patches, not prose
Every change arrives as a small patch: create, set, retire. Apply them in order and your table matches the text so far, with nothing to parse.
Evidence on every value
Each value points back to the words it was read from, so you can show it, check it and trust it.
A probability on every change
Act at once on the sure ones and send the rest for review.
Changes of mind
When the text later says otherwise (“actually, make it Friday”), the value changes with it, and the old one is kept in the history.

Against the generative alternative

Reading against writing

The usual way to keep a state with a language model is to have it write the state out: after each message, the whole table again. Every update then costs seconds, grows with the state, and can carry values nobody said. We gave Kanji and its own backbone, the generative model it is built on, the same 148 lines of a team's incident channel, on the same machine, scored by the same count.

  • Kanji
  • its generative backbone, writing the table after each line
  • 23 sfor Kanji to read all 148 lines, handed to it at once
  • 4 min 10 sfor its backbone to do the same, ten times as long

The backbone writes the same table after every line, as function calls, with the whole conversation in its context. One run each, read once, on an M4 Max. Field F1 counts every field of every object in the table after each line against the gold table. A development measurement, as is everything on this page.

Field F1 compares every field of every object in Kanji's table with a gold table after each line. Joint goal accuracy is the share of dialogue turns in which every slot of the state is right. SDT (Gupta et al., 2022) writes the state out as text, reading the whole dialogue again at every turn; MetaASSIST (Ye et al., 2022) picks each slot's value from a list made for MultiWOZ in advance. Kanji reads each turn once, with any schema.
